# Fix DeepSeek Thinking Tool Choice Error

## Goal

Fix DeepSeek `deepseek-v4-pro` requests failing with `Thinking mode does not support this tool_choice` while preserving the local OCS answer server contract and Pydantic AI validation/fallback behavior.

## What I Already Know

* Runtime log shows the AI path returns fallback answer because the provider rejects the request with HTTP 400.
* Config currently uses `AI_BASE_URL=https://api.deepseek.com` and `AI_TEXT_MODEL=deepseek-v4-pro`.
* `app.llm.create_answer_agent()` uses `Agent(..., output_type=ModelAnswer)`.
* In PydanticAI 1.102.0, a bare Pydantic model output type defaults to tool-based structured output.
* Tool-based output with no direct text output resolves `tool_choice` to a forced/required tool choice.
* PydanticAI's built-in DeepSeek provider profile marks `deepseek-v4-*` as not supporting forced `tool_choice`.
* The existing prompt already requires a JSON object with `answer` and `analysis`; the app validates and normalizes that at the gateway boundary.

## Requirements

* DeepSeek `deepseek-v4-pro` requests must not send a forced output-tool `tool_choice` that the API rejects in thinking mode.
* Keep returning a validated `ModelAnswer` object from `PydanticAIAnswerer.answer()`.
* Preserve fallback behavior for provider failures and malformed/invalid model output.
* Preserve text vs. image model routing and image input construction.
* Do not hard-code credentials or model defaults.

* [ ] Existing LLM gateway tests still pass.

## Technical Approach

Use PydanticAI's prompted structured output for `ModelAnswer` so the model is instructed to emit JSON and PydanticAI still validates the response, but no output tool or forced `tool_choice` is sent. This matches the existing prompt contract and avoids DeepSeek thinking-mode/tool-choice incompatibility without bypassing PydanticAI.

## Decision (ADR-lite)

**Context**: DeepSeek thinking-capable models reject the forced `tool_choice` generated by PydanticAI's default tool output mode for a bare Pydantic model.

**Decision**: Prefer `PromptedOutput(ModelAnswer)` for this app's answer schema instead of tool-output structured mode.

**Consequences**: The provider request avoids output tools and forced tool choice. The schema is enforced through prompt instructions and PydanticAI validation/retries rather than function-tool forcing, which is appropriate for this app's simple two-field JSON answer contract.

* Changing model selection settings beyond the structured output mode.
* Performing live API calls against DeepSeek during automated tests.
